# Sideroad

Vetted local trades for rural properties in Erin, Hillsburgh, Ballinafad and Wellington County, Ontario.
Homeowners ask for help by web form or text; trades sign up free; a founder coordinates from a small
admin dashboard. The full brief is in [docs/SPEC.md](docs/SPEC.md).

**Phase 1 (this code): validate demand with almost no automation.**

- Landing page (the supplied design, forms wired up)
- Homeowner request form, with an optional photo, stored as a Request with status `NEW`
- Out-of-area postal codes go to a waitlist, with a friendly message
- "Join as a trade" signup, stored as a Trade with status `PENDING_REVIEW`
- Texts to the Twilio number create or append to a Request keyed by phone number. Every message is stored.
- Password-protected admin: list and filter requests, trades and the waitlist, change statuses, read
  each thread, and send a text by hand
- An email to the founders for every new request, trade signup and inbound text
- CASL: explicit consent on every form, with the exact wording and a timestamp stored. STOP is honoured.

## Stack

TypeScript on Node 22, Fastify, server-rendered Eta templates (no frontend build, no client JS),
Postgres through Drizzle ORM, Twilio for SMS, Nodemailer over SMTP for email, and Vitest for tests.
It deploys to one VPS with Caddy for HTTPS and systemd running the app as a non-root user.
See [deploy/DEPLOY.md](deploy/DEPLOY.md).

## Run it locally

```bash
# Postgres 16 (any local install works; or: docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=sideroad postgres:16)
createuser -s sideroad; createdb -O sideroad sideroad; createdb -O sideroad sideroad_test

npm install
cp .env.example .env          # fill in SESSION_SECRET and ADMIN_PASSWORD_HASH at least
npm run hash-password          # paste the output into .env
npm run migrate:dev
npm run dev                    # http://localhost:3000, admin at /admin
```

The app refuses to start if a required setting is missing. Twilio and SMTP need real values
to actually send, but forms and the dashboard work locally without them: notification emails fail
and are logged, and the request is still saved.

To try inbound SMS locally, expose port 3000 with a tunnel (for example `cloudflared tunnel --url
http://localhost:3000`), set `PUBLIC_BASE_URL` to the tunnel URL, and point a Twilio number's
messaging webhook at `<tunnel>/webhooks/twilio/sms`.

## Tests

```bash
npm test          # needs the sideroad_test database; override with TEST_DATABASE_URL
npm run typecheck
```

The tests cover request intake (validation, consent, coverage and waitlist, photos, honeypot),
trade signup, inbound SMS (signature checks, threading, retries, concurrent texts, trades, MMS,
STOP/START) and the admin (auth, CSRF, status changes, sending and delivery receipts, opt-out blocking).
Twilio and email are replaced with fakes; the database is real.

## Layout

```
config/coverage.json      towns and postal prefixes we serve (edit this, no code change needed)
migrations/               SQL migrations generated by drizzle-kit (npm run db:generate after schema changes)
src/
  index.ts                starts the server (reads .env)
  app.ts                  Fastify setup, security headers, error pages
  config.ts               environment validation
  db/                     schema, connection, migration runner
  domain/                 services list, coverage rules, phone numbers, CASL wording, dates
  services/               intake (forms), sms (inbound, sending, receipts), notify, photos, auth, audit
  routes/                 public pages, Twilio webhooks, admin/*
views/                    Eta templates; landing.eta is the supplied design
deploy/                   systemd unit, Caddyfile, backup script, DEPLOY.md
docs/                     the spec and the original landing page HTML
test/                     Vitest suites
```

## How it behaves

- **Coverage.** A postal code is checked against `postalPrefixes`. A covered town named in the
  location counts as in the area. Anything else, such as a bare road name, is kept as a normal request
  marked "check area" for a human to decide. The waitlist is used only when a postal code is clearly
  outside the list, so an empty list never turns anyone away.
- **Text threading.** A text from a known trade's number is filed under that trade. Otherwise it joins
  the sender's most recent open request (`NEW`, `CONTACTED` or `MATCHED`) if that request was active in
  the last 14 days. If not, it starts a new request. A per-number database lock stops two quick texts
  from opening two requests, and Twilio's message ID stops retries being stored twice.
- **STOP.** STOP, UNSUBSCRIBE, CANCEL, END, QUIT and ARRET add the number to `sms_opt_outs` and mark its
  SMS consent withdrawn. START and UNSTOP remove it. The dashboard refuses to text an opted-out number.
  Twilio's own opt-out handling stays on as a second layer.
- **Consent.** Every form has an unticked checkbox with the wording from `src/domain/consent.ts`, and
  the same text is stored with each consent record. To change wording, add a new version rather than
  editing an old one. Someone who texts first is recorded as implied consent to reply to their inquiry.
- **No auto-replies.** Phase 1 sends nothing automatically except emails to the founders.
- **Admin.** One shared password (scrypt hash in `.env`). Each founder types their name at login so the
  audit log shows who changed or sent what. Sessions last 12 hours in a signed, httpOnly, SameSite=strict
  cookie. Every admin form carries a CSRF token.
- **Photos.** Up to 10 MB each. The file type is checked from the file's contents (JPEG, PNG, WebP, GIF or
  HEIC). Photos are stored outside the web root and served only to a logged-in admin.

## Before launch

- [ ] Put the real postal code prefixes in `config/coverage.json` and check the town list.
- [ ] Replace `[TRADE NAME]` and `[PRICE]` in the landing page's example conversation (`views/landing.eta`),
      or keep them if they're meant to read as placeholders. They were left as-is from the design.
- [ ] Have the privacy page (`views/privacy.eta`) and the consent wording reviewed.
- [ ] Buy the Canadian Twilio number, set its webhook, and fill in `.env` on the server.
- [ ] Set up SMTP (any provider) and send a test request to confirm the alert email arrives.
- [ ] Set up off-server copies of the nightly backups.
